How the live meeting works — best option first

Best: voice call here in Muse. A real interview is spoken, timed, and under pressure. Voice trains timing, follow-ups, handling “I don’t know” out loud, English fluency and confidence. This page is the companion — prep before, record after — it does not replace the live voice interview.
  1. Start the voice call in Muse and say “ClearCaptions mock interview shuru karo” — or pick another target job.
  2. 30–45 minutes, one job per meeting. One question at a time, with follow-ups, just like a real panel.
  3. After each answer: score 1–5, 2–3 concrete fixes, then retry the same question better.
  4. At the end: hiring verdict — hire / borderline / no-hire — 3 strengths, 3 fixes, and the exact 3 questions to practise next.

Full real interview — what every session covers

Not only technical questions. In real-interview order:

StageTimeWhat happens
Opening / small talk2 minGreeting, audio/camera check, warm-up
HR + intro5–8 minTell me about yourself, why this role / company, why leaving, salary, remote, availability, authorisation
Technical + portfolio + scenarios20–25 minWordPress deep dive, portfolio walkthrough, live debugging / scenarios, performance, security, accessibility, SEO, GA4/GTM
Behavioural + architecture5–8 minSTAR stories, mentoring, stakeholders, first 30 / 90 days on their platform
Your questions + closing5 minJaved’s questions for them, closing, next steps, follow-up note
Verdict + feedback5 minScores, hire / borderline / no-hire, 3 strengths, 3 fixes, homework

Scoring: 1 = vague / no example, 3 = clear + one real example, 5 = clear + quantified example + what you would do in their stack.

10 likely questions — ClearCaptions #211

Tap a question to see the structure to practise — not a script to memorise. Answer in your own words, with a real example.

1. Tell me about yourself — 60–90 seconds

WordPress-first. 11 years, 100+ sites, Development Manager at Rezolvemed and Rising Revenue Solutions. End with why ClearCaptions / this platform role fits.

2. Walk me through your portfolio — 100 sites

918 checked, best 100 chosen, 94 WordPress / 6 custom, 32 categories. Pick 2–3 sites and go deep: what you built, what problem it solved, what you would improve now.

3. How do you build a custom WordPress theme / plugin from scratch?

One real example. Requirements → architecture → custom post types / fields → security / sanitisation → testing → deployment. Name the project.

4. How do you handle site speed and Core Web Vitals on a heavy WordPress site?

Measure first (what tool, what metric), then the fixes in order: caching, images, CSS/JS, fonts, hosting, database. Give a before / after example.

5. How do you approach WordPress security, backups and maintenance?

Hardening, updates, backups (frequency + restore test), monitoring, what you do when a site is compromised. Real routine, not a list.

6. Tell me about a time you mentored a developer or set a technical standard

STAR: situation, what you changed, what the developer / team did differently after, what the result was. This is a strength — lead with a named example.

7. How have you connected WordPress to an external system via REST API?

Lead capture, routing, data quality. Then the honest bridge to Salesforce — see Gap drills below. Do not claim Salesforce if you have not done it.

8. How do you implement GA4 / GTM, attribution and consent management?

GTM setup, GA4 events, attribution, consent mode. Flag OneTrust / server-side GTM honestly: concepts vs hands-on depth — confirm before claiming.

9. How do you make a site WCAG-accessible, and how do you test it?

Semantic HTML, keyboard, contrast, focus, forms, alt text. How you test: tools + manual keyboard / screen-reader checks. Give one fix you actually made.

10. What would you do in your first 30 days on our platform?

Listen first: audit the platform, themes/plugins, performance, security, accessibility, analytics, CI/CD. Then quick wins, then the 90-day plan. Ask them what their pipeline looks like.

Gap drills — answer honestly, never claim what is not confirmed

Structure for every gap: (1) closest real work I have done, (2) what is new here, (3) my 30-day plan to deliver it.

TypeScript
“My production work is JavaScript and PHP. I have not shipped production TypeScript. I read it comfortably and work with structured JS — here is how I would ramp in week one.”
CI/CD
Talk Git workflow, staging → production, release discipline, code review. Then ask them how their pipeline works — turn the gap into a question.
Salesforce
“I have built WordPress ↔ external-system integrations with REST APIs — lead capture, routing, data quality. Salesforce itself is new to me. Here is how I would approach the first integration, step by step.”
Strengths to lead with
Custom themes, plugins, custom dashboards; WooCommerce, Elementor, ACF, Gutenberg; site speed, security, maintenance; Development Manager at two companies.

Rule: honest bridge, never a false claim. TypeScript, CI/CD, Salesforce, Python, Docker and Divi need Javed’s one-time confirmation before they are claimed anywhere.
